# MCP server

{/* TODO: add client screenshots once available */}

Windrunner exposes a [Model Context Protocol](https://modelcontextprotocol.io)
server so AI agents such as Codex, Claude Desktop, and Cursor can operate the
system natively — finding work, reading full context, recording findings, and
updating status without custom HTTP plumbing.

## Endpoint and transport

| Setting | Value |
| --- | --- |
| URL | `http://localhost:8066/mcp` |
| Transport | Streamable HTTP (stateless) |
| Auth | `Authorization: Bearer <API key>` — same keys as the REST API |

Enable/disable with `WINDRUNNER_MCP_ENABLED` (`true` by default).

## Connecting clients

Codex CLI:

```bash title="Terminal"
codex mcp add windrunner \
  --url http://localhost:8066/mcp \
  --header "Authorization: Bearer wr_k_..."
```

Claude Desktop (`claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "windrunner": {
      "type": "http",
      "url": "http://localhost:8066/mcp",
      "headers": {
        "Authorization": "Bearer wr_k_..."
      }
    }
  }
}
```

## Tool catalog

| Tool | Scope required | Description |
| --- | --- | --- |
| `list_projects` | `projects:read` | Projects visible to the key owner |
| `search_work_items` | `work_items:read` | Typo-tolerant full-text search across items, entries, and relationship reasons |
| `get_work_item` | `work_items:read` | Full picture of one item: fields, assignees, entries, relationships |
| `list_my_work` | *(any valid key)* | Items assigned to the key owner across all visible projects |
| `add_entry` | `entries:write` | Add a comment, finding, answer, or evidence to an item |
| `update_work_item_status` | `work_items:write` | Change only the status of an item |
| `create_work_item` | `work_items:write` | Create a TASK, QUESTION, APPROVAL, REVIEW, or DECISION |
| `link_relationship` | `relationships:write` | Create a typed link such as BLOCKED_BY between two items |

## Safety model

- Every action is attributed to the API-key owner in the audit log.
- Writes trigger the same notifications as human actions.
- Project-level authorization still applies: a key can only see and modify
  projects its owner can.
- No delete tools are exposed.
